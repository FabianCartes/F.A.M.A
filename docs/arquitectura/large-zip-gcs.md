## Specs

- S1: «Normalización, migración, resúmenes y páginas». «No eliminar información existente sin comprobación y estrategia de recuperación.» Acceptance: explicit, transactional, verified backfill preserving original JSON; normalized indexed per-file/issue records; bounded summaries and stable pages for files/classes/issues. Confirmed seams: authenticated HTTP, explicit migration with synthetic databases, rendered panel. Replace full responses and their frontend consumers together; abort migration on discrepancies without partial activation.
- S2: «Workers, leases, exclusión y admisión». «Impedir que un worker cuyo lease perdió vigencia publique resultados después de ser reemplazado.» Acceptance: persistent jobs and recovery, bounded status, independent leases and short publication exclusion; no long global lock or network transaction.
- S2a: «Tablas, restricciones y migración explícita; admisión idempotente por operación». «Reservar capacidad de ejecución mediante una operación atómica, no con count() seguido de inserción sin coordinación.» «Una repetición idéntica devuelve el mismo trabajo.» «Una repetición con parámetros distintos se rechaza.» Execution admission includes owner/global limits and recoverable capacity release, not physical disk reservations or byte quotas.
- S2b: «Dos workers no ejecutan válidamente el mismo intento; el obsoleto no publica». «Heartbeat separado: una operación lenta no provoca reemplazos por impedir el heartbeat.» «Staging por intento: un intento antiguo no modifica el resultado del nuevo.» Every progress/result/publication requires the current job/token, admissible state and live lease; persisted queue is authoritative.
- S2c: «POST preview: admite una validación.» «POST confirm: admite la verificación y publicación asociadas al token revisado.» «POST sync: admite una sincronización explícita.» «Respuesta 202: identificador y referencia de estado.» «GET: etapa, progreso, resultado y error resumidos.» «202 no se muestra como éxito final; recargar permite recuperar el trabajo.» Owner-only query/cancel/retry; polling renews neither activity nor lease; explicit confirmation and no automatic sync.
- S2d: «Hashing, decodificación y red fuera del candado de dataset.» «Revalidación corta de revisión y titularidad antes de publicar.» «Preservar el journal, los hashes y las garantías de fsync.» «Recuperar el estado de publicación pendiente antes de admitir una publicación incompatible.» Cleanup must not delete active or recoverable staging or compete from HTTP; full asynchronous cleanup remains Cut5.
- S2e: «Usar relojes controlados y barreras de sincronización, evitando pruebas dependientes de esperas arbitrarias.» Required proof: simultaneous owner/global admission; double claim; admitted and running crash recovery; stale heartbeat/progress/publication rejection; independent heartbeat and staging; rename-before-commit recovery without duplicates; independent imports and readable state/pages during slow work; ownership; inert polling; protected cleanup; coordinated UI. «La evidencia de caída/reinicio necesitará un procedimiento separado con almacenamiento sintético privado y sin debilitar la guarda existente.» Independent persistence/security/concurrency verification and operation manual required; no live service startup or deployment.
- S3: «ZIP recibido» «10 GiB»; «Contenido descomprimido por importación» «15 GiB»; «Dataset acumulado» «15 GiB»; «Archivos únicos por dataset» «50.000». «Un GiB equivale a 1024³ bytes.» «Fragmentos de 16 MiB, inicialmente secuenciales.» Acceptance: durable idempotent chunks, ownership, complete-prefix hash verification on resume, exact boundaries and atomic quota/reservation admission. Technical defaults are configurable proposals, not benchmarks.
- S3a: «El usuario puede subir varios dataset, pero cada uno de estos tiene el tope de 10gb de peso del zip». «empezemos de una a la vez». «admisión por presupuesto»; «límites por usuario y globales»; «liberación recuperable de reservas». Acceptance: one concurrent receipt/import per owner, not a cumulative dataset-storage cap; explicit additive migration and transactional admission with durable reservations. Retain current conservative received/expanded limits until T4. HTTP and explicit migration are the public backend test seams; no live migration.
- S3b: «Reintentar el mismo fragmento es idempotente.» «Reutilizar su posición con contenido diferente se rechaza.» «Se rechazan huecos, solapamientos y exceso de bytes.» «Solo se reconoce progreso que pueda recuperarse después de una caída.» Acceptance: authenticated receipt status/chunk/finalize/cancel, immutable completed archive, durable sequential chunks and bounded hash pages.
- S3c: «Leer incrementalmente todos los fragmentos del prefijo ya aceptado.» «Comparar sus hashes con el registro de recepción.» «Verificando archivo para reanudar». Acceptance: rendered-panel seam, incremental browser reads and complete accepted-prefix verification before continuing, including changed middle chunk with identical size and endpoints.
- S3d: «La vista previa expondrá estos valores. La confirmación volverá a comprobar cuota y revisión del destino antes de publicar.» «dataset_size_limit»; «dataset_entry_limit». Acceptance: unique projected dataset bytes/files at preview and publication, exact boundaries and competing confirmations under existing fencing. No ZIP64/decoder containment or automatic limit increase in T3.
- S4: «ZIP64 con offset grande y con contadores extendidos.» «El plazo cooperativo existente no equivale a aislamiento del sistema operativo.» Acceptance: bounded EOCD/ZIP64 precheck before entry allocation, real expanded-byte accounting, validated original WAV bytes, killable isolated decoder with resource limits and no network/GCS credentials.
- S5: «Reinicio después de rename y antes de commit.» «Limpieza y reanudación concurrentes.» «Un fallo posterior de limpieza no convierte una importación publicada en fallida.» Acceptance: preserved hash/fsync journal recovery, unique membership, revision/quota recheck, recoverable claimed asynchronous cleanup respecting activity and leases.
- S6: «Se suben WAV individuales, no ZIP intermedios.» «Una revisión parcial no se presentará como completa.» Acceptance: bounded recoverable object batches, verified generations/integrity, immutable complete authorized manifest separate from mutable progress. Manifest preserves canonical paths/classes/provenance/hashes/sizes and supports reconstruction without original ZIP or local membership lists.
- S7: «Exportación que funciona sin ZIP original ni objetos locales.» «Descarga con varios rangos autorizados.» «No utilizar: fetch → response.blob() → URL.createObjectURL() para estas exportaciones.» Acceptance: asynchronous generation-bound verified ZIP64 reconstruction; native authorized resumable download with length/identity/expiry and active-download-safe cleanup; no silent incomplete export or long Next rewrite dependency.
- S8: «No renderizar ni validar toda la colección en una sola respuesta.» «Mantener los documentos del proyecto bajo docs/:» «No crear documentación paralela bajo odd/.» Acceptance: bounded UI and integration checks, operational manuals/limits/manifest/recovery ADRs, index and board updates; report all failed/skipped/pending checks. «Usar datos sintéticos, temporales privados y almacenamiento simulado.» «Operaciones sobre GCS real sin autorización explícita.» remain excluded, as do training, conversions, shared publication and installations by inference.
