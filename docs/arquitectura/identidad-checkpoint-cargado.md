# Identidad del checkpoint cargado
Objetivo: vincular el checkpoint registrado, la instancia predictora y el resultado sin afirmar atestación continua de tensores.
Rama: `fix/prediction-view-truthfulness`; base: `1cff14c693325032283bde3a5608202619d1037e`. Entrega: commits locales autorizados; sin push ni despliegue autorizados. Pruebas: pytest y Vitest.

## Specs
- S1 — Solicitud autorizada: «Procede con la implementación», en respuesta a la propuesta: «La carga y el hash deben utilizar los mismos bytes.» y «Asociar ese hash a la instancia, por ejemplo como `loaded_checkpoint_sha256`.» La identidad cargada se obtiene de la misma instantánea que se deserializa; se publica solo después de cargar correctamente.
- S2 — Propuesta aceptada: «Si no coinciden, no usar silenciosamente esa instancia: cargar y validar la versión esperada o rechazar la predicción con un error claro.» La identidad esperada proviene del registro persistido cuando existe; se rechazan bytes incompatibles y las instancias cacheadas incompatibles, sin inferencia ni persistencia del resultado rechazado.
- S3 — Decisión humana: «Bloquearlos hasta registrar su hash». Descripción elegida: «Rechazar la predicción si falta el hash esperado. Ofrece validación estricta, pero deshabilita modelos históricos hasta regularizar su registro.» Esto aplica a modelos persistidos; no migrar ni completar automáticamente hashes históricos.
- S4 — Propuesta aceptada: «cada resultado debería registrar el hash de la instancia que realmente lo produjo, no volver a leer el hash del archivo después de inferir.» Incluir también rutas de silencio y ruido. Conservar el contrato superior de respuesta, usando `detalles.loaded_checkpoint_sha256`.
- S5 — Propuesta aceptada: «Distinguir: Checkpoint registrado; Checkpoint cargado por el predictor; Checkpoint del informe de evaluación». El catálogo añade `loaded_checkpoint_sha256` opcional; la UI muestra la procedencia de la instancia y del resultado, no inventa identidad para modelos o respuestas sin ese dato y conserva la advertencia sobre atestación de parámetros.
- S6 — Límites de pruebas confirmados: «Confirmar esos límites (recomendado)», para predictor, API y vista de Predicción. Ejemplo autorizado: «Incluye cargar A, reemplazar el archivo por B y comprobar que nunca se atribuya B a una inferencia hecha con A.» Conservar comportamiento previo válido de carga lazy, clasificación, silencio/ruido, catálogo e informes.
