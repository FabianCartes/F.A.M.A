# Traslado explícito de historia y adopción de una cuenta existente

La base histórica PostgreSQL 18 carece de revisión Alembic y utiliza CASCADE entre predicción y corrección, mientras el esquema vigente protege esa historia con RESTRICT. Se decide copiar las filas mediante una operación explícita hacia un esquema vigente vacío, conservando IDs, campos, hash de contraseña y siguiente valor de secuencias. El origen se lee en una instantánea; el destino se valida, serializa y copia en una transacción. Se reconocen únicamente las dos variantes conocidas de ese vínculo; otros cambios de esquema se rechazan. No se restaura directamente el dump 18 sobre PostgreSQL 16 ni se fuerza una revisión sobre el origen.

El traslado no convierte nombres históricos en autoría o permisos: nuevas asignaciones, solicitudes, sesiones, recuperación y procedencia autorizante quedan vacías; los campos nuevos de incorporación permanecen NULL. Los modelos conservan sus indicadores históricos, sin elegir un predeterminado. Una sincronización histórica pendiente bloquea el traslado para revisión, evitando publicar una intención antigua al arrancar el destino. La vista previa produce una huella de filas y siguientes valores de secuencias que debe coincidir al aplicar; un destino ocupado no se mezcla ni sobrescribe.

La adopción se separa del alta inicial: una CLI local comprueba servicios, esquema, permisos diarios, almacenamiento del nodo y un administrador ya activo. Cierra el perfil sin crear, ascender, reactivar o cambiar la contraseña de esa cuenta. Una intención privada vincula perfil, cuenta y un evento de auditoría reservado; permite reanudar una publicación local fallida después del commit SQL sin duplicar el evento. Una instalación completada no se reabre. Se conserva el bloqueo PostgreSQL y la exclusión local del nodo de los ADR 0040/0042; no se añade una nueva tabla de coordinación.

El coste es mantener una operación de traslado y una adopción específicas, además de realizar el corte final con los escritores identificados. Esto permite comprobar el destino antes de habilitarlo y preservar el origen, frente a reinterpretar su esquema o reutilizar el asistente para crear otra cuenta. Los archivos y el catálogo se concilian por separado: copiar filas no acredita existencia de audios, integridad de pesos, validez científica o preparación de toda la instalación.
