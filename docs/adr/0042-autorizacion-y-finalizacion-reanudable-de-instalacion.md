# Autorización del nodo y finalización reanudable de primera instalación

El asistente se autoriza mediante un código aleatorio de 15 minutos emitido en el equipo, vinculado al origen web. El servidor conserva solo su digest; el navegador lo mantiene en memoria, fuera de URL y almacenamiento persistente. Las cuentas web aún no existen y no pueden ser el mecanismo de autorización inicial. Tras finalizar, el código no reabre la instalación aunque los servicios estén caídos.

Se conserva el esquema ya migrado. Antes de crear el administrador se guarda una intención privada con su hash de contraseña y la configuración vinculada; después se confirma la transacción SQL y se finaliza el registro local. Un bloqueo de archivo serializa operaciones del nodo y un bloqueo asesor PostgreSQL protege la comprobación de base vacía y la creación frente a otros nodos. El reintento solo puede reconocer la cuenta exacta de esa intención, sin cambiar credenciales ni adoptar una base existente. Una tabla nueva de coordinación exigiría otra migración privilegiada; la intención local permite resolver esta transición sin conservar al migrador en la aplicación.

La configuración queda inmovilizada al empezar la finalización. El estado completado se escribe al final y permanece independiente de disponibilidad, según el ADR 0040. El backend requiere reiniciar su servicio para cargar la entrada funcional después de finalizar; el asistente lo comunica y no inicia modelos durante la preparación. Las pruebas acordadas cruzan HTTP/CLI y los formularios visibles, usando PostgreSQL desechable y simulación únicamente en servicios externos o fallos del sistema de archivos.
