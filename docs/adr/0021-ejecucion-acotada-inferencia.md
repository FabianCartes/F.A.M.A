# ADR 0021: El trabajo real conserva el cupo de inferencia

La inferencia admite una solicitud por proceso, sin cola de solicitudes, y responde 503 con `Retry-After: 5` cuando está ocupada. El predictor síncrono se ejecuta fuera del event loop. Un lease compartido conserva el cupo mientras exista el request o su trabajo real; el hilo crea y elimina su propio temporal. Cancelar la espera HTTP no cancela PyTorch ni libera recursos que aún usa el hilo.

Se descarta liberar el cupo en el `finally` del request sin una referencia del worker: permitiría inferencias simultáneas después de una cancelación. Se usa un lock de threading, no un semáforo asociado a un event loop, porque el estado es por proceso y debe funcionar también entre loops distintos. No se introduce infraestructura de jobs. La sesión SQLAlchemy permanece en el handler, fuera del hilo predictor; un request cancelado no persiste un resultado tardío.

## Consecuencias y límites

- BEXEC-2 adquiere el cupo en middleware ASGI antes de leer el cuerpo de `POST /api/predict`; el handler reutiliza ese lease sin doble adquisición. Las llamadas directas conservan adquisición propia. El middleware libera su referencia incluso ante error del parser, desconexión o cancelación.
- El contador verifica bytes reales antes de entregarlos al parser, hasta 110 MiB inclusive; no confía en `Content-Length`. Ante exceso usa la excepción del parser para cerrar spools parciales y reemplaza su respuesta por un único 413 JSON. CORS permanece externo al control para conservar errores visibles desde el navegador.
- Antes de GCS se valida metadata real con soundfile: contenedor WAV/WAVEX/RF64, frames/rate/canales positivos y duración hasta 300 s inclusive, sin recorte ni política nueva de MIME, codec, frecuencia o canales. El chequeo no decodifica el waveform; no se afirma un presupuesto de memoria decodificada.
- El lease protege también el trabajo síncrono de metadatos, además del hilo predictor, incluso al desaparecer su waiter. Los fallos tardíos se observan sin fabricar resultados; se conservan los errores HTTP del [ADR 0015](./0015-fallos-explicitos-inferencia-y-validacion.md).
- BEXEC-3 mantiene el wrapper async y pasa su función de subida **síncrona** al runner del lease. Inferencia opta por timeout SDK de 60 s y `retry=None`; callers sin opciones conservan los cuatro argumentos posicionales y defaults anteriores. El hilo SDK conserva el cupo tras cancelación y no inicia predicción/persistencia tardía al desaparecer el waiter durante la subida. No es un deadline total de transferencia ni un rollback de objetos externos.
- Las etapas emiten tiempos/categorías e ID opaco generado internamente, sin datos privados. Upload/validación/predict registran fin desde el worker real; cancelar HTTP solo registra fin de la espera. Python 3.14 puede registrar excepciones tardías de `shield` aunque tengan observer: el worker transporta resultado/error como valor y solo un waiter activo vuelve a lanzar el error, sin registrar traceback crudo.
- BEXEC-4 aplica 270 s de presupuesto asíncrono a `POST /api/predict` desde admisión, incluyendo parser/validación/subida/predicción. Devuelve 504 JSON solo antes de headers; una respuesta iniciada se aborta sin segundo status. Cancelación externa no se convierte en timeout. Es un presupuesto blando: no preempta DB síncrona ni mata hilos. Starlette instalado captura BaseException y cierra spools parciales al cancelar el parser, comprobado por prueba.
- Next recibe `experimental.proxyTimeout: 300000` para todos los rewrites HTTP externos, no solo inferencia; no cambia rutas locales ni WebSocket. La prueba usa loader y helper reales con backend falso de 35 s; build/router completo y navegador siguen pendientes.
- No hay shutdown que mate hilos: un cierre ordenado depende del servidor y del drenaje del executor. Un worker bloqueado puede prolongar el cierre; un proceso terminado abruptamente puede dejar temporales. No se afirma una prueba de lifespan ni de shutdown productivo.
- El límite no es global entre workers/réplicas. La evidencia de ingreso usa umbrales reducidos, no transporte real de 110 MiB; los budgets no constituyen SLA wall-clock global.
